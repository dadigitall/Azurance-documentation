## Pour qui

Cette documentation s'adresse aux équipes qui intègrent Azurance dans un logiciel métier déjà utilisé au guichet, en pharmacie, en clinique, dans un laboratoire ou dans un back-office assureur:

- éditeurs d'ERP hospitaliers, cliniques, pharmacies et laboratoires;
- assureurs, mutuelles et gestionnaires de portefeuilles santé;
- intégrateurs chargés de sécuriser les échanges entre SI métier et APIs Azurance.

## Points d'accès officiels

| Espace | Production | Sandbox |
| --- | --- | --- |
| ERP Prestataires | `https://provider-api.elenami.com` | `https://provider-api-sandbox.elenami.com` |
| ERP Assurances | `https://insurer-api.elenami.com` | `https://insurer-api-sandbox.elenami.com` |

Tous les environnements utilisent `X-Api-Key`. Une clé sandbox ne fonctionne que sur l'environnement sandbox; une clé production ne fonctionne que sur l'environnement production.

## Principes d'intégration

- Les ERP appellent uniquement les domaines API publics documentés.
- Une clé API détermine le partenaire, l'environnement, les scopes et le contexte autorisé.
- Les clés API restent côté serveur: proxy backend, job d'intégration, middleware hospitalier ou connecteur assureur.
- Les exemples utilisent des UUID et codes métier publics.
- Les URLs non listées dans cette documentation ne font pas partie du contrat public.
- Les changements de contrat public sont documentés dans le changelog avant publication.
