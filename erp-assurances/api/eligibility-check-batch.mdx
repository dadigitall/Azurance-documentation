---
title: "Vérifier des éligibilités en lot"
description: "Exécute plusieurs contrôles d'éligibilité dans une même requête."
openapi: "/openapi/insurer-api.openapi.yml POST /api/v1/eligibility/check-batch"
---

Cet endpoint exécute plusieurs contrôles d'éligibilité en une seule requête. Il est adapté aux flux de pré-admission ou aux imports en masse.

## Scope requis

`eligibility.check`

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `checks` | array | oui | Liste des contrôles à exécuter (jusqu'à 20). Chaque élément suit le même schéma que `POST /api/v1/eligibility/check`. |
| `checks[].identifier` | string | oui | Identifiant de la personne assurée (numéro de police ou équivalent). |
| `checks[].coverage_code` | string | oui | Code de la couverture à vérifier. |
| `checks[].amount` | number | non | Montant du soin à évaluer. |
| `checks[].provider_id` | integer | non* | Identifiant numérique du prestataire. Requis si `provider_uuid` absent. |
| `checks[].provider_uuid` | string | non* | UUID du prestataire. Requis si `provider_id` absent. |
| `checks[].beneficiary_id` | string | non | Bénéficiaire si le soin ne concerne pas le souscripteur. |
| `checks[].service_date` | string | non | Date du soin au format `YYYY-MM-DD`. |
| `checks[].purpose` | string | non | `PRECHECK` (défaut) ou `CLAIM_SUBMISSION`. |

\* `provider_id` ou `provider_uuid` est obligatoire pour chaque contrôle.

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data` | array | Résultats dans le même ordre que les contrôles envoyés. |
| `data[].eligibility_check_uuid` | string (uuid) | Identifiant de la vérification. |
| `data[].eligible` | boolean | Éligibilité du contrôle. |
| `data[].status` | string | `ELIGIBLE` ou `INELIGIBLE`. |
| `data[].error_code` | string | `null` si éligible, sinon un code d'erreur. |
| `data[].reason` | string | Message lisible si non éligible. |
| `data[].member` | object | Informations de la personne assurée. |
| `data[].subscription` | object | Souscription active. |
| `data[].coverage` | object | Garantie vérifiée. |
| `data[].reimbursement` | object | Présent si `amount` était fourni. |

## Cas d'usage

- Vérifier l'éligibilité d'un groupe d'assurés avant un séjour hospitalier.
- Contrôler un import de prestations planifiées.
- Automatiser la pré-admission en établissement.

## Bonnes pratiques

Limitez la taille du lot aux plafonds indiqués dans le contrat OpenAPI. Un contrôle individuel en échec ne fait pas échouer le lot : chaque résultat est indépendant. Fournissez un `Idempotency-Key` pour éviter les doublons en cas de retry.
