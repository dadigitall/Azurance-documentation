---
title: "Créer une souscription"
description: "Crée un contrat pour un membre du portefeuille."
openapi: "/openapi/insurer-api.openapi.yml POST /api/v1/subscriptions"
---

Cet endpoint crée un contrat (souscription) rattachant un assuré à un plan d'assurance pour une période donnée.

## Scope requis

`insurer.members.manage`

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `policyholder_uuid` | string | oui | Identifiant de l'assuré. |
| `plan_code` | string | oui | Code du plan souscrit. |
| `effective_date` | string | oui | Date de début de couverture au format `YYYY-MM-DD`. |
| `expiry_date` | string | non | Date de fin de couverture. Déduite du plan si absent. |
| `premium_amount` | number | non | Montant de la prime. |
| `premium_frequency` | string | non | Fréquence de prime (`MONTHLY`, `QUARTERLY`, `YEARLY`). |
| `metadata` | object | non | Métadonnées libres. |

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `uuid` | string | Identifiant de la souscription créée. |
| `policyholder_uuid` | string | Identifiant de l'assuré. |
| `subscription_number` | string | Numéro de souscription. |
| `plan_code` | string | Code du plan. |
| `plan_name` | string | Nom du plan. |
| `status` | string | Statut initial (`ACTIVE`). |
| `effective_date` | string | Date de début effective. |
| `expiry_date` | string | Date de fin effective. |
| `premium_amount` | number | Montant de la prime. |
| `premium_frequency` | string | Fréquence de prime. |
| `annual_coverage_limit` | number | Plafond annuel. |
| `annual_used_amount` | number | Consommation annuelle. |
| `remaining_coverage` | number | Couverture restante. |
| `created_at` | string | Date de création au format ISO 8601. |

## Cas d'usage

- Souscrire un nouveau contrat lors de l'adhésion d'un client.
- Activer une couverture suite à un avenant.
- Créer un contrat retroactif pour une affaire en attente.

## Bonnes pratiques

Vérifiez que l'assuré et le plan existent avant l'appel. Fournissez un `Idempotency-Key` pour garantir l'idempotence et éviter les doublons en cas de retry.
