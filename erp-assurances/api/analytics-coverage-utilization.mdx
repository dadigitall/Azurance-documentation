Cet endpoint mesure la consommation des plafonds de couverture par plan, afin d'anticiper les dépassements et d'ajuster les garanties.

## Scope requis

`insurer.analytics.view`

## Paramètres de requête

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `period` | string | non | Code de période (`month`, `quarter`, `year`). Défaut : `year`. |
| `from` | string | non | Date de début au format `YYYY-MM-DD`. |
| `to` | string | non | Date de fin au format `YYYY-MM-DD`. |
| `plan_id` | string | non | Identifiant du plan à isoler. |
| `coverage_type` | string | non | Code de garantie à filtrer. |

## Indicateurs retournés

| Champ | Type | Description |
| --- | --- | --- |
| `period_start` | string | Date de début de la période. |
| `period_end` | string | Date de fin de la période. |
| `by_coverage` | array | Consommation par garantie (`coverage_code`, `utilization_rate`, `claims_count`, `total_used`, `total_limit`). |
| `high_utilization_coverages` | array | Garanties à forte consommation (`coverage_code`, `utilization_rate`). |

## Cas d'usage

- Détecter les garanties systématiquement saturées en cours d'année.
- Ajuster les plafonds lors de la refonte d'un plan.
- Anticiper les demandes de déblocage exceptionnel pour les assurés proches du plafond.

## Bonnes pratiques

Un taux d'utilisation élevé n'est pas forcément un signal négatif : il peut indiquer une garantie bien adaptée. Croisez avec le nombre de membres concernés pour distinguer une consommation diffuse d'une concentration sur quelques assurés.
