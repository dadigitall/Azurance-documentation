---
title: "Consulter un plan"
description: "Retourne le détail d'un plan d'assurance par son code métier."
openapi: "/openapi/insurer-api.openapi.yml GET /api/v1/plans/{planId}"
---

Cet endpoint retourne le détail complet d'un plan d'assurance. Côté BFF, le paramètre de chemin est transmis comme `code` au policy-service : utilisez donc le `plan_code` du plan, par exemple `GOLD` ou `PLAN_ESSENTIAL`.

## Scope requis

`insurer.policies.view`

## Paramètres de chemin

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `planId` | string | oui | Code métier du plan (`plan_code`). Le nom du paramètre reste `planId` dans l'OpenAPI pour partager le même path item que `PUT` et `DELETE`, mais le GET attend un code. |

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data.uuid` | string | Identifiant du plan. |
| `data.plan_code` | string | Code métier du plan. |
| `data.plan_name` | string | Nom du plan. |
| `data.plan_type` | string | Type du plan. |
| `data.description` | string | Description commerciale. |
| `data.base_premium` | number | Prime de référence. |
| `data.premium_frequency` | string | Fréquence de prime. |
| `data.annual_coverage_limit` | number | Plafond annuel. |
| `data.lifetime_coverage_limit` | number | Plafond à vie. |
| `data.dependent_age_limit` | integer | Âge limite des ayant droit. |
| `data.waiting_period_days` | integer | Délai de carence en jours. |
| `data.grace_period_days` | integer | Délai de grâce en jours. |
| `data.effective_date` | string | Date d'effet. |
| `data.expiry_date` | string\|null | Date d'expiration. |
| `data.is_active` | boolean | Indique si le plan est actif. |
| `data.coverages` | array | Garanties incluses. |
| `data.exclusions` | array | Exclusions. |
| `data.created_at` | string | Date de création. |

## Cas d'usage

- Afficher le détail d'un plan dans un back-office.
- Vérifier les plafonds avant un contrôle d'éligibilité.
- Consulter les garanties incluses lors d'une souscription.

## Bonnes pratiques

Pour récupérer un plan, passez son `plan_code`. Pour modifier ou supprimer un plan, utilisez `plans-update` ou `plans-delete` avec l'identifiant attendu par ces opérations.
