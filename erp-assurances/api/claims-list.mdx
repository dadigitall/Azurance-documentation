---
title: "Lister les claims"
description: "Liste les demandes de remboursement reçues des prestataires."
openapi: "/openapi/insurer-api.openapi.yml GET /api/v1/claims"
---

Cet endpoint retourne la liste paginée des claims (demandes de remboursement) reçus des prestataires. Les filtres permettent de cibler un périmètre précis.

## Scope requis

`insurer.claims.view`

## Paramètres de requête

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `page` | integer | non | Numéro de page. Défaut : `1`. |
| `per_page` | integer | non | Nombre d'éléments par page. Défaut : `20`. |
| `status` | string | non | Filtre par statut (`SUBMITTED`, `UNDER_REVIEW`, `APPROVED`, `REJECTED`, `PAID`). |
| `provider_uuid` | string | non | Filtre par identifiant prestataire. |
| `subscription_id` | string | non | Filtre par souscription. |
| `policyholder_id` | string | non | Filtre par assuré. |
| `service_date_from` | string | non | Date de prestation minimale au format `YYYY-MM-DD`. |
| `service_date_to` | string | non | Date de prestation maximale au format `YYYY-MM-DD`. |

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data` | array | Liste des claims. |
| `data[].uuid` | string | Identifiant public du claim. |
| `data[].claim_number` | string | Numéro du claim. |
| `data[].status` | string | Statut. |
| `data[].provider_uuid` | string | Identifiant du prestataire. |
| `data[].provider_name` | string | Nom du prestataire. |
| `data[].subscription_id` | string | Identifiant de la souscription. |
| `data[].coverage_type_code` | string | Code de garantie. |
| `data[].service_date` | string | Date de prestation. |
| `data[].amount_claimed` | number | Montant réclamé. |
| `data[].amount_approved` | number | Montant approuvé. |
| `data[].currency` | string | Devise. |
| `meta` | object | Métadonnées de pagination. |

## Cas d'usage

- Lister les claims en attente de décision pour le back-office.
- Filtrer les claims d'un prestataire pour un audit.
- Extraire les claims d'une période pour un rapport.

## Bonnes pratiques

Combinez les filtres `service_date_from` et `service_date_to` pour limiter le volume. Pour un suivi temps réel des nouveaux claims, abonnez-vous aux webhooks plutôt que de scruter cette liste.
