---
title: "Lister les webhooks"
description: "Récupère la liste des webhooks configurés par l'assureur."
openapi: "/openapi/insurer-api.openapi.yml GET /api/v1/webhooks"
---

Cet endpoint récupère la liste des webhooks configurés par l'assureur. Utilisez-le pour vérifier vos abonnements et leurs statuts.

## Scope requis

`insurer.webhooks.view`

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data` | array | Liste des webhooks. |
| `data[].uuid` | string | Identifiant unique du webhook. |
| `data[].name` | string | Nom du webhook. |
| `data[].target_url` | string | URL de callback. |
| `data[].event_types` | array | Types d'événements abonnés. |
| `data[].is_active` | boolean | Indique si le webhook est actif. |
| `data[].metadata` | object | Métadonnées libres. |
| `data[].created_at` | string | Date de création. |
| `data[].updated_at` | string | Date de mise à jour. |
| `meta` | object | Métadonnées de pagination. |

## Cas d'usage

- Vérifier les webhooks actifs avant un déploiement.
- Auditer les abonnements après un incident de livraison.
- Identifier un webhook désactivé à réactiver.

## Bonnes pratiques

Ne stockez pas le `secret` des webhooks côté client : il n'est jamais retourné en lecture. Pour modifier un webhook, utilisez `webhooks-update`. Pour le supprimer, utilisez `webhooks-delete`.

## Exemple de réponse

```json
{
  "data": [
    {
      "uuid": "web_sandbox_001",
      "name": "Payment Notifications",
      "target_url": "https://example.com/webhooks/payments",
      "event_types": ["payment.created", "payment.succeeded", "payment.failed"],
      "is_active": true,
      "metadata": {},
      "created_at": "2026-02-01T10:00:00.000000Z",
      "updated_at": "2026-02-01T10:00:00.000000Z"
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 1
  }
}
```
