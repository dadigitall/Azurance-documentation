---
title: "Approuver une demande d'adhésion réseau"
description: "Valide une demande d'adhésion au réseau prestataire."
openapi: "/openapi/insurer-api.openapi.yml PATCH /api/v1/providers/network-requests/{uid}/approve"
---

Cet endpoint approuve une demande d'adhésion réseau en statut `PENDING`. La relation `care_network` passe en statut `active` côté registre réseau et devient visible comme relation conventionnée.

## Scope requis

`insurer.providers.manage`

## Paramètres de chemin

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `uid` | uuid | oui | Identifiant public de la demande/relation réseau (`relationship_uid`). |

## Workflow

1. Listez les demandes via `GET /api/v1/providers/network-requests?status=pending`.
2. Vérifiez le prestataire, ses documents administratifs et les métadonnées de la demande.
3. Appelez cet endpoint pour approuver la demande.
4. La relation devient `active` et sera visible dans `GET /api/v1/providers/network-relationships`.

## Réponse

La réponse retourne la relation réseau mise à jour. Le statut est `active` dans la réponse brute de l'organization-service.

| Champ | Type | Description |
| --- | --- | --- |
| `data.uid` | uuid | Identifiant public de la relation. |
| `data.source_uid` | uuid | UID de l'organisation assureur. |
| `data.target_uid` | uuid | UID de l'organisation prestataire. |
| `data.type` | string | Type de relation (`care_network`). |
| `data.status` | string | Statut interne (`active`). |
| `data.initiated_by` | string\|null | Origine de la demande. |
| `data.rejected_reason` | string\|null | Toujours null après approbation. |
| `data.starts_at` | string\|null | Date de début si configurée. |
| `data.ends_at` | string\|null | Date de fin si configurée. |
| `data.metadata` | object | Métadonnées conservées de la demande. |
| `data.created_at` | date-time | Date de création de la demande. |
| `data.updated_at` | date-time | Date d'approbation. |

## Erreurs fréquentes

| Statut | Cause |
| --- | --- |
| `404` | La demande n'existe pas. |
| `422` | La demande n'est plus en statut `pending` et ne peut pas être approuvée. |
