---
title: "Lister les notifications"
description: "Historique des notifications envoyées à l'assureur."
openapi: "/openapi/insurer-api.openapi.yml GET /api/v1/notifications"
---

Cet endpoint retourne l'historique des notifications envoyées à l'assureur. Utilisez-le pour consulter les alertes reçues et leur statut de lecture.

## Scope requis

`insurer.notifications.view`

## Paramètres de requête

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `page` | integer | non | Numéro de page. Défaut : `1`. |
| `per_page` | integer | non | Nombre d'éléments par page. Défaut : `20`. |

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data` | array | Liste des notifications. |
| `data[].id` | integer | Identifiant de la notification. |
| `data[].uid` | string | Identifiant public. |
| `data[].event_type` | string | Type d'événement. |
| `data[].channel` | string | Canal (`EMAIL`, `SMS`, `PUSH`). |
| `data[].status` | string | Statut d'envoi. |
| `data[].subject` | string | Sujet. |
| `data[].body` | string | Contenu. |
| `data[].sent_at` | string | Date d'envoi. |
| `data[].read_at` | string | Date de lecture, présente si lue. |
| `data[].created_at` | string | Date de création. |
| `meta` | object | Métadonnées de pagination. |

## Cas d'usage

- Afficher la liste des notifications dans un back-office.
- Identifier les notifications non lues.
- Consulter l'historique des alertes sur une période.

## Bonnes pratiques

Pour marquer une notification comme lue, utilisez `notifications-mark-read`. Pour ajuster les canaux de réception, utilisez `notifications-preferences-update`.
