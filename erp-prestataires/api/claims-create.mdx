---
title: "Soumettre un claim"
description: "Soumet un claim, refait la vérification finale et réserve les plafonds."
openapi: "/openapi/provider-api.openapi.yml POST /api/v1/claims"
---

Cet endpoint soumet un claim après un recheck final obligatoire. Il valide l'éligibilité, calcule les plafonds applicables, réserve les montants et crée le claim. Aucun claim n'est créé si le check final est refusé.

## Scope requis

`claims.create`

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `subscription_id` | string | oui | Identifiant de souscription. |
| `policyholder_id` | string | oui | Identifiant du titulaire de police. |
| `coverage_type_code` | string | oui | Code de garantie visée. |
| `service_date` | date | oui | Date de la prestation. |
| `amount_claimed` | number | oui | Montant réclamé. |
| `currency` | string | oui | Devise, `XOF` par défaut. |
| `items` | array | oui | Lignes de prestation (`MedicationReferenceLine`). |
| `covered_person_type` | string | non | `policyholder` ou `beneficiary`. |
| `covered_person_uid` | string | non | Identifiant de la personne couverte. |
| `consent_ref` | uuid | non | Référence de consentement fort. |
| `service_execution_uid` | uuid | non | Prestation enregistrée liée au claim. |
| `prior_authorization_uid` | uuid | non | Pré-autorisation consommée. |
| `precheck_eligibility_uuid` | uuid | non | UUID d'un précheck d'éligibilité réutilisé pour le check final. |

## Workflow

1. Effectuer un précheck via `POST /api/v1/eligibility/check` et conserver `precheck_eligibility_uuid`.
2. Enregistrer la prestation via `POST /api/v1/service-executions` si applicable.
3. Uploader les justificatifs via `POST /api/v1/media/uploads`.
4. Soumettre le claim avec les `items`, `documents` et `precheck_eligibility_uuid`.
5. Suivre le statut via `GET /api/v1/claims/{claimId}`.

## Réponse

La réponse `201` contient le claim créé avec son identifiant, son statut et les réservations de plafond. Un `422` indique un check final refusé (aucun claim créé) ; un `503` signale un service interne indisponible (réessayer avec backoff sur `5xx`).
