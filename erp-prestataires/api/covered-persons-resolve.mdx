---
title: "Retrouver une personne couverte"
description: "Recherche bornée d'une personne couverte avant consentement."
openapi: "/openapi/provider-api.openapi.yml POST /api/v1/covered-persons/resolve"
---

Cet endpoint résout une personne couverte à partir d'un identifiant métier, sans exposer de données médicales. Il est utilisé avant l'initiation d'un consentement pour récupérer l'identifiant stable de la personne à autoriser.

## Scope requis

`covered_persons.resolve`

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `identifier_type` | string | oui | Type d'identifiant (voir ci-dessous). |
| `identifier` | string | oui | Valeur de l'identifiant recherché. |
| `contract_uid` | uuid | non | Identifiant du contrat de couverture pour restreindre la recherche. |
| `subscription_uid` | uuid | non | **Déprécié** — alias de `contract_uid`, conservé pour compatibilité. |
| `limit` | integer | non | Nombre de candidats, maximum 10. |

## Types d'identifiants

| `identifier_type` | Usage |
| --- | --- |
| `npi` | Numéro d'identification personnel. |
| `phone_number` | Numéro de téléphone. |
| `policy_number` | Numéro de police. |
| `contract_number` | Numéro du contrat de couverture (recommandé). |
| `subscription_number` | **Déprécié** — alias de `contract_number`. |
| `member_number` | Numéro de membre. |
| `beneficiary_number` | Numéro de bénéficiaire. |

## Réponse

Chaque candidat représente **la couverture d'une personne sous un contrat donné**. Une même personne couverte par plusieurs contrats (police individuelle + adhésion à une police collective employeur, par exemple) apparaît sur plusieurs lignes, une par contrat.

Le bloc `contract` décrit le contrat de couverture effectif : `contract_uid`, `contract_number`, `plan_code`, `plan_name`, `status`, `effective_date`, `expiry_date`, `annual_coverage_limit`, `annual_used_amount`. Les champs `subscription_uid` et `subscription_number` sont des alias dépréciés de `contract.contract_uid` et `contract.contract_number`.

Une recherche non indexée, un wildcard ou un identifiant trop court renvoie une erreur `400` ; un rate limit dépassé renvoie `429`.
