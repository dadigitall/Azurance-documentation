title: "Créer une prestation effectuée"
description: "Enregistre la prestation réellement effectuée par le prestataire."

---

Cet endpoint enregistre une prestation réellement effectuée par le prestataire. Contrairement au précheck d'éligibilité, cet endpoint atteste que l'acte a eu lieu et sert de base au claim ultérieur.

## Scope requis

`service_executions.create`

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `subscription_uid` | string (uuid) | oui | Identifiant de la souscription. |
| `covered_person_type` | string | oui | `policyholder` ou `beneficiary`. |
| `covered_person_uid` | string | oui | Identifiant de la personne couverte. |
| `coverage_type_code` | string | oui | Code du type de couverture. |
| `service_date` | date | oui | Date de la prestation. |
| `provider_reference` | string | non | Référence interne du prestataire. |
| `consent_ref` | string (uuid) | oui | Référence de consentement validée. |
| `items` | array | oui | Lignes de prestation (médicaments, actes). |

## Workflow

1. Résoudre la personne couverte via `POST /api/v1/covered-persons/resolve`.
2. Obtenir un consentement via `POST /api/v1/consent-requests` puis `POST /api/v1/consent-requests/{uid}/verify`.
3. Enregistrer la prestation via cet endpoint avec le `consent_ref`.
4. Soumettre le claim via `POST /api/v1/claims` en référençant le `service_execution_uid` retourné.
