---
title: "Créer une consultation"
description: "Enregistre une nouvelle consultation (encounter)."
openapi: "/openapi/provider-api.openapi.yml POST /api/v1/encounters"
---

Cet endpoint déclare une nouvelle consultation ou hospitalisation dans le dossier clinique de l'assuré. Il est le point d'entrée du parcours clinique : les actes médicaux, documents et ordonnances sont ensuite rattachés à cette consultation.

## Scope requis

`clinical.encounters.manage`

## Types de consultation

| `encounter_type` | Usage |
| --- | --- |
| `consultation` | Consultation ambulatoire standard. |
| `hospitalization` | Admission ou hospitalisation. |
| `emergency` | Passage aux urgences. |
| `surgery` | Acte chirurgical. |
| `procedure` | Geste thérapeutique ou procédure. |
| `imaging` | Examen d'imagerie médicale. |
| `laboratory` | Examen de biologie ou de laboratoire. |

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `insured_uid` | uuid | oui | Identifiant UUID de l'assuré. |
| `encounter_type` | string | oui | Type de consultation (voir ci-dessus). |
| `encounter_date` | date | oui | Date de la consultation. |
| `discharge_date` | date | non | Date de sortie (hospitalisation uniquement). |
| `icd10_codes` | array | conditionnel | Au moins un code CIM-10 si `chief_complaint` est absent ou vide. |
| `chief_complaint` | string | conditionnel | Motif de consultation (max 500) si `icd10_codes` est absent ou vide. |
| `clinical_summary` | string | non | Résumé clinique (antécédents, examen, conclusion, max 5000). |
| `department` | string | non | Service ou département (ex: `cardiologie`, `urgences`). |
| `attending_physician` | string | non | Médecin ou praticien responsable. |

`icd10_codes` ou `chief_complaint` doit être fourni. Les deux peuvent être envoyés ensemble, mais un tableau vide et un motif vide ne sont pas acceptés.

## Chiffrement

Les réponses de cet endpoint sont chiffrées via JWE. Récupérez d'abord la clé publique RSA via `GET /api/v1/auth/encryption-key` pour déchiffrer la réponse côté ERP.

## Exemple de requête

```json
{
  "insured_uid": "9a1b2c3d-4e5f-4061-8f2a-1b2c3d4e5f60",
  "encounter_type": "consultation",
  "encounter_date": "2026-08-15",
  "icd10_codes": ["R10.9"],
  "chief_complaint": "Douleur abdominale",
  "department": "urgences",
  "attending_physician": "Dr. KOUASSI"
}
```
