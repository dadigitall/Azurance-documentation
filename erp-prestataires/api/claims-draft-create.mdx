---
title: "Créer un brouillon de claim"
description: "Crée un claim en statut draft sans check final ni réservation de plafond."
openapi: "/openapi/provider-api.openapi.yml POST /api/v1/claims/draft"
---

Cet endpoint crée un brouillon de claim en statut `draft`. Aucun check final d'éligibilité n'est effectué et aucun plafond n'est réservé. En revanche, chaque ligne est déjà validée : couverture connue du plan, identifiants cliniques résolus contre les référentiels, cohérence type↔couverture. Le brouillon peut être complété avec des documents justificatifs via `POST /api/v1/claims/{claimId}/documents`, puis soumis via `POST /api/v1/claims/{claimId}/submit`.

## Scope requis

`claims.create`

## En-têtes

| Header | Requis | Description |
| --- | --- | --- |
| `X-Api-Key` | oui | Clé API prestataire. |
| `X-Request-Id` | non | Identifiant de corrélation. |
| `Idempotency-Key` | recommandé | UUID pour éviter les soumissions en double. |

## Champs du body

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `contract_uid` | uuid | oui* | Identifiant du contrat de couverture. |
| `subscription_id` | string | non | **Déprécié** — alias de `contract_uid`. |
| `policyholder_id` | string | oui | Identifiant du titulaire de police. |
| `coverage_type_code` | string | non* | Garantie par défaut des lignes sans code propre. Obligatoire si une ligne n'a pas son propre code. |
| `service_date` | date | oui | Date de la prestation (`YYYY-MM-DD`). |
| `amount_claimed` | number | oui | Montant réclamé (min 0.01). |
| `currency` | string | non | Devise, `XOF` par défaut. |
| `items` | array | oui | Lignes de facture — voir table ci-dessous. |
| `covered_person_type` | string | non | `policyholder` ou `beneficiary`. |
| `covered_person_uid` | string | non | Identifiant de la personne couverte. |
| `consent_ref` | uuid | non | Référence de consentement fort. |
| `service_execution_uid` | uuid | non | Prestation enregistrée liée — chaque ligne facturée doit alors correspondre à un item de l'exécution (`EXECUTION_MISMATCH`). |
| `prior_authorization_uid` | uuid | non | Pré-autorisation consommée. |
| `precheck_eligibility_uuid` | uuid | non | UUID d'un précheck d'éligibilité réutilisé. |
| `provider_reference` | string | recommandé | Référence ERP unique par prestataire — `409 PROVIDER_REFERENCE_CONFLICT` si rejouée. |
| `documents` | array | non | Documents justificatifs à attacher. |
| `notes` | string | non | Notes libres. |

## Champs d'une ligne `items[]`

| Champ | Type | Description |
| --- | --- | --- |
| `description` | string | Libellé de la ligne (requis). |
| `quantity` | number | Quantité (requis, ≥ 1). |
| `unit_price` | number | Prix unitaire (requis). |
| `coverage_type_code` | string | Code de garantie de la ligne ; hérite du code global si omis. Non couverte par le plan → `422 ITEMS_NOT_ELIGIBLE` à la soumission. |
| `prior_authorization_uid` | uuid | PA approuvée couvrant cette ligne — requise si sa couverture impose une PA, sinon la ligne passe `PENDING_AUTHORIZATION` et le claim est bloqué en `UNDER_REVIEW`. |
| `prescription_uid` + `prescription_line_uid` | uuid | Ligne d'ordonnance exécutée. Doit exister et appartenir à l'ordonnance (`PRESCRIPTION_LINE_NOT_FOUND`/`MISMATCH`). Son `line_type` détermine l'`item_type` dérivé. |
| `medical_act_uid` | uuid | Acte du référentiel — rejeté si inconnu/inactif (`MEDICAL_ACT_NOT_FOUND`/`INACTIVE`) ou incohérent avec le code (`MEDICAL_ACT_MISMATCH`). |
| `medical_act_code` | string | Code acte (CCAM/ICHI). Inconnu → warning `UNKNOWN_REFERENCE_CODE` ; rejeté à la soumission si le plan a des règles par acte. Quand il résout, `medical_act_uid`/`category`/`chapter` canoniques sont enrichis. |
| `medical_act_category`, `medical_act_chapter` | string | Axes déclarés — remplacés par les valeurs canoniques quand l'acte est résolu. |
| `medication_product_uid` | uuid | Produit Azurance — rejeté si inconnu ou inactif (`MEDICATION_PRODUCT_NOT_FOUND`/`INACTIVE`). |
| `medication_code`, `prescribed_medication_code`, `presentation_uid` | string | Codes nomenclature — inconnus → warning `UNKNOWN_REFERENCE_CODE`, non bloquant. |
| `erp_product_code`, `erp_product_name`, `erp_mapping_confidence` | string/number | Snapshot du produit ERP et confiance de mapping (0–1). |
| `prescribed_quantity`, `dispensed_quantity` | number | Quantité prescrite vs délivrée. |
| `substitution_reason` | string | Motif de substitution si le délivré diffère du prescrit. |
| `batch_number` | string | Numéro de lot. |
| `metadata` | object | Métadonnées libres de ligne. |

## Exemple de réponse

```json
{
  "data": {
    "draft_uid": "8f4b2c1d-0000-4000-8000-000000000001",
    "claim_number": "CLM-2026-001234",
    "claim_hash": "9f2c4b8e1a7d3f5b6c0e2a4d8f1b3c5e7a9d1f3b5c7e9a1d3f5b7c9e1a3d5f7b9c",
    "status": "draft",
    "amount_claimed": 58500,
    "currency": "XOF",
    "service_date": "2026-01-15",
    "coverage_type_code": null,
    "items_count": 3
  },
  "warnings": null
}
```

`claim_hash` fige le contenu de la facture — il est revérifié à la soumission. `warnings` liste les identifiants cliniques déclarés mais inconnus des référentiels, au format `items.{index}.{champ}:CODE` (ex. `items.0.medical_act_code:UNKNOWN_REFERENCE_CODE`). Un warning ne bloque pas le brouillon, mais un acte non résolu peut bloquer la soumission si le plan applique des règles par acte.

## Workflow

1. Créer un brouillon via `POST /api/v1/claims/draft`.
2. Attacher les documents justificatifs via `POST /api/v1/claims/{claimId}/documents`.
3. Soumettre le brouillon via `POST /api/v1/claims/{claimId}/submit` avec le `consent_ref`.
4. Suivre le statut via `GET /api/v1/claims/{claimId}`.

## Erreurs

| Code | Description |
| --- | --- |
| 401 | Clé API manquante ou invalide. |
| 403 | Scope `claims.create` manquant. |
| 409 | `PROVIDER_REFERENCE_CONFLICT` — la `provider_reference` est déjà utilisée sur un claim actif. |
| 422 | Lignes invalides — `errors` détaille chaque champ fautif (`items.{index}.{champ}` : `PRESCRIPTION_LINE_NOT_FOUND`, `MEDICAL_ACT_NOT_FOUND`, `MEDICATION_PRODUCT_NOT_FOUND`, `ITEM_COVERAGE_INCOMPATIBLE`, `UNKNOWN_REFERENCE_CODE` si plan strict). |
| 503 | Service interne indisponible — réessayer avec backoff. |
