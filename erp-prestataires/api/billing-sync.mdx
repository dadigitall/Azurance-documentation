---
title: "Synchroniser la facturation"
description: "Flux incrémental pour récupérer les événements billing."
openapi: "/openapi/provider-api.openapi.yml GET /api/v1/billing/sync"
---

Cet endpoint expose un flux incrémental des événements billing (bordereaux, paiements, allocations) visibles par le prestataire. Il est conçu pour remplacer le polling massif : on appelle l'endpoint avec un curseur, on traite la page renvoyée, puis on rappelle avec le curseur suivant jusqu'à épuisement.

## Scope requis

`billing.sync`

## Paramètres de requête

| Paramètre | Type | Description |
| --- | --- | --- |
| `cursor` | string | Curseur de pagination renvoyé par la page précédente. |
| `updated_after` | date-time | Borne temporelle pour ne récupérer que les événements modifiés après cette date. |

## Réponse

| Champ | Type | Description |
| --- | --- | --- |
| `data` | array | Page d'événements billing. |
| `data[].cursor` | string | Curseur de l'événement, à utiliser pour la pagination. |
| `data[].event_id` | string | Identifiant unique de l'événement. |
| `data[].event_type` | string | Type (`payable_invoice.issued`, `payable_invoice.paid`, `payment.created`, `payment.succeeded`, `payment.failed`). |
| `data[].aggregate_type` | string | Type de ressource concernée (`PayableInvoice`, `Payment`). |
| `data[].aggregate_uuid` | string | Identifiant de la ressource concernée. |
| `data[].payload` | object | Snapshot de la ressource au moment de l'événement. |
| `data[].updated_at` | string | Date de l'événement au format ISO 8601. |
| `meta.next_cursor` | string | Curseur à passer au prochain appel. Absent s'il n'y a plus de page. |

## Workflow de synchronisation

1. Premier appel sans `cursor` (ou avec `updated_after` pour une reprise datée).
2. Traiter chaque événement de la page renvoyée.
3. Rappeler l'endpoint avec le `meta.next_cursor` renvoyé dans la réponse.
4. Recommencer jusqu'à ce que la réponse ne contienne plus `next_cursor`.

## Bonnes pratiques

Conservez le dernier curseur traité côté ERP pour reprendre la synchronisation après un redémarrage. Pour les événements temps réel, complétez ce flux par une souscription webhook (`payment.created`, `payable_invoice.issued`) plutôt que de réduire l'intervalle de polling.
