---
title: "Lister les prescriptions autorisées"
description: "Retourne les prescriptions consultables avec consentement valide."
openapi: "/openapi/provider-api.openapi.yml GET /api/v1/covered-persons/{coveredPersonType}/{coveredPersonUid}/prescriptions"
---

Cet endpoint liste les ordonnances d'une personne couverte consultables après consentement fort. L'accès est filtré selon le consentement validé et le prestataire authentifié : seules les prescriptions autorisées dans le périmètre du consentement sont renvoyées.

## Scope requis

`clinical.prescriptions.view`

## Paramètres de chemin

| Paramètre | Type | Description |
| --- | --- | --- |
| `coveredPersonType` | string | `policyholder` ou `beneficiary`. |
| `coveredPersonUid` | string | Identifiant de la personne couverte. |

## Paramètres de requête requis

| Paramètre | Type | Description |
| --- | --- | --- |
| `subscription_uid` | uuid | Identifiant de la souscription concernée. |
| `consent_ref` | uuid | Référence du consentement fort validé. |

## Paramètres de requête optionnels

| Paramètre | Type | Description |
| --- | --- | --- |
| `page` | integer | Numéro de page. |
| `per_page` | integer | Résultats par page. |

## Workflow

1. Résoudre la personne couverte via `POST /api/v1/covered-persons/resolve`.
2. Initier un consentement via `POST /api/v1/consent-requests` avec le purpose `prescription_access`.
3. Valider le challenge via `POST /api/v1/consent-requests/{uid}/verify` pour obtenir `consent_ref`.
4. Appeler cet endpoint avec `subscription_uid` et `consent_ref`.

## Réponse

La réponse contient les ordonnances filtrées selon le consentement et le prestataire. Si le consentement est expiré, révoqué ou insuffisant, l'API retourne une erreur `403`.

## Chiffrement

Les réponses de cet endpoint sont chiffrées via JWE. Récupérez la clé publique RSA via `GET /api/v1/auth/encryption-key` pour déchiffrer la réponse.
